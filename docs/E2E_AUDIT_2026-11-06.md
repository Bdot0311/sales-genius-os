- **Static.** Many existing tests read source text. They catch a check being deleted. They do not execute it.

## Architecture (as read, not assumed)

- **App:** Vite + React + React Router. Data access from the browser goes through the Supabase client and row-level security.
- **API:** Deno edge functions in `supabase/functions`. Workers and the agent use the service role, which bypasses RLS, so ownership has to be checked in code.
- **Auth:** User JWTs via `supabase.auth.getUser`. Cron and internal calls use the service role or `INTERNAL_TRIGGER_SECRET`.
- **Tenancy:** `user_id` on leads, sequences, enrollments, drafts, and sent mail. RLS on `sequence_enrollments` previously checked only that the enrollment's `user_id` was the caller.
- **AI:** `_shared/ai-provider.ts` routes to Bedrock when configured and otherwise to the Lovable gateway. Call sites include `agent-run`, `agent-chat`, `agent-test`, `ai-coach`, `generate-email`, `generate-followup-suggestion`, `generate-sequence`, `generate-blog-post`, `research-lead`, `research-account`, `score-lead`, `score-lead-v2` (the number is deterministic; the model rephrases the reason), `parse-lead-query`, `analyze-reply`, `analyze-domain`, `build-agent`, `check-copy-risk`, `check-email-rubric`, `apply-rubric-suggestion`, `draft-changelog`, `map-account-committee`, `refill-blog-topics`. Batch drafts go through `_shared/draft-one.ts` into `generate-email`.

## Fixes

### High — another account's lead could be enrolled and mailed

`sequence_enrollments` insert policy required `auth.uid() = user_id` only. The foreign keys only require the lead and sequence to exist. The dispatcher runs as service role, loads `lead:leads(*)`, queues mail to `lead.contact_email`, and updated that lead with no `user_id` filter.

- Migration `20261106043000_enrollment_same_tenant.sql` requires the lead and the sequence to belong to the caller.
- MCP enroll (`src/lib/mcp/tools/enroll-lead.ts` and the generated bundle) and `agent-chat` check both rows before insert. The agent uses the service role, so the policy alone does not cover it.
- `process-sequence-step` pauses a mismatched enrollment and does not queue mail or write the lead. The lead update that remains is also scoped with `user_id`.

### High — `send-email` trusted a client `leadId`

The invalid-address check loaded `leads` by id only. Another account's verification status could block or allow the send, and the foreign id was stored on `sent_emails`. The lookup is now `id` plus `user.id`. A miss returns `404 lead_not_found` and does not send.

### High — `analyze-reply` loaded and wrote any lead id

An authenticated caller could put another account's contact into the prompt and attach a draft and a sequence update to that id. The lead is loaded with `user_id`. A miss drops the id. Drafts and `apply_reply_to_sequence` use the owned id only.

### High — autonomous first touch sent with no research

`agent-run` logged an empty research block and still called `send-email`. The prompt says not to invent. Nothing enforced it.

- Company-specific assertions ("you just launched", "congrats on the round") are blockers when the research block is empty, so the quality loop discards them instead of sending.
- A draft that stays within role and industry is saved and labelled. It is not sent, and follow-ups are not queued.
- Follow-ups are checked with the same blockers and `auditEmail` before `scheduleFollowUps`. A failing touch is not queued.
- `auditEmail` now receives the research block, account context, and lead fields as `verifiedProof`, so a figure that is actually in the brief is allowed and one that is not is blocked.

### High — autonomous replies could promise an offer or a figure

Interested, objection, and meeting replies were checked for deliverability and then sent. `agentProhibitions` was prompt text, and the objection and meeting prompts did not include it.

Generated replies are now blocked when `replySendBlockers` finds a figure absent from the account proof (and, for objections, the library proof points) or an unauthorised discount, roadmap, guarantee, or compliance claim. The objection and meeting prompts include the prohibitions as well. A calendly link the account configured is not passed through the model.

### Medium — introduction drafts ignored the thin-research refusal

Outreach Studio sends `blockOnThinResearch: true`. `draftForLead` did not, so batch and autonomous jobs could save and schedule a first touch `generate-email` would have refused in the studio. Introduction goals now set the flag. `research_too_thin` is returned as skipped, not as a draft and not as a hard failure to retry.

### Medium — research observations were stored with invented sources

`research-lead` persisted model observations whose `source` was whatever the model wrote. Observations whose source is not a URL fetched in that run are dropped. If nothing cited remains and there is no signal event, confidence is forced to `low`. This does not prove the sentence occurs on the page. It refuses a citation the run never retrieved. `what_they_do` and `hooks` are still model text.

### Medium — recalled background was labelled as verified research

`generate-email` nested "NOT VERIFIED" recall inside the `VERIFIED RESEARCH` heading. The recall is appended after that heading, under its own label.

### Medium — the coach UI received a body it does not parse

`ai-coach` was switched to `stream: false` so claims could be checked, and it returned JSON `{ advice }`. Coach, Live Coaching, and Playbooks only read SSE `data:` lines with `choices[0].delta.content`, so the checked advice never appeared. The function still checks first, strips figures that are not in the account context, and returns one SSE chunk. A reply that is only an invented figure is replaced with an abstention. The monthly cap comparison is `>=`, matching the page, which previously allowed one message past the plan limit. The 20–30% close-rate line in the prompt is labelled as a rough planning range, not this account's result.

### Medium — agent builder saved an ungrounded persona

`checkGrounded` already dropped `company_context` and `value_props` that were not in the user's description. `persona` and `role_instructions` were saved raw and then copied into every later prompt. They go through the same check. A failure stores an empty string.

## Product behavior that changed on purpose

When company research is missing, an autonomous agent no longer sends the first touch. A clean category-only draft is saved for a person, with the action text saying it was not sent. A draft that asserts a company-specific event is discarded by the existing quality hold. This matches the failure described in `docs/AGENT_RELIABILITY_SCOPE.md`. If the desired behavior is to skip even the category-only draft, or to send it unattended, that is an owner decision.

## Second pass

The items below were open after the first commit (`581ece0c`). CI on that commit failed one test: `environment-doc` requires every file in `docs/` to be linked from the README, and `E2E_AUDIT_2026-11-06.md` was not. That is fixed in this pass. The other checks on that commit (typecheck, schema-refs, both edge-function jobs) succeeded.

### Credit balances

`apply_search_meter` locks the subscription row (`FOR UPDATE`), applies the credit and daily counters together, refuses a gated debit that would pass zero, and otherwise clamps at zero. `enrich-lead` and the free-tier search path call it instead of writing a balance they just read. Refunds use the same function.

Local Postgres (`postgresql://audit@127.0.0.1/audit_test`, not production): eight concurrent debits from a balance of 1, one applied, balance left at 0. Two concurrent inserts of the same sequence step, one rejected by the unique index. That test is `src/lib/runtime-guards.test.ts`. It no-ops when that database is unreachable, which is the case in GitHub CI. It ran here.

### Duplicate sequence steps

Unique index `sent_emails_one_live_sequence_step` on `(enrollment_id, sequence_step)` for live statuses. `process-sequence-step` treats `23505` as already queued and advances the enrollment only if `current_step` is still the old value.

### Gmail accepted, row not saved

`deliverReserved` inserts a `pending` row, sets `send_attempted_at`, then calls Gmail, then updates that row. If the update fails, the response is HTTP 200 with `success: false`, `retryable: false`, `code: "accepted_unpersisted"`. A second attempt finds the pending row and does not call Gmail. A provider rejection marks the row `failed` with `sent_at` null. The scheduled sender does not call `failEmail` after Gmail has accepted; `send_attempted_at` is already set, so that row is not sent again.

A mock store test calls the provider once when the save fails, and a second `deliverReserved` does not call it. A second mock test races two reservations and allows one provider call.

### Bounded scans

`sweepSlice` picks one page from a count. `detect-suspicious-activity` reads 40 pro subscriptions per minute and rotates the page. Per-user error, deletion, and key-creation checks are counts, not `select('*')`. The unusual-hour read is capped at 200 rows and the alert says `+` when the cap is hit, so the count is a lower bound. `sync-inboxes` counts active Google integrations and reads one page of `MAX_USERS` (100), rotating every five minutes. These are bounds on rows read per pass. They are not a measured production throughput.

### Templates at send time

`queuedCopyBlockers` runs in `process-sequence-step` before a step is queued and in `process-scheduled-emails` before Gmail. A company-event phrase whose words are not in the lead research is not queued and not sent. The scheduled row is marked failed with the reason, before `begin_scheduled_email_send`.

### Unsourced reply rates

Removed from the sequence builder: "8.3% reply rates vs. 4.1%" and "42% of replies come from follow-ups". Removed from Analytics: the 6x, 42%, and 15%+ cards, and "3–5x higher reply rates". No replacement numbers were added. The remaining comparison lines on Analytics are labelled as planning constants, not this account's mailbox and not figures this product has verified. `OUTBOUND_KB` still holds the constants for those comparison lines.

### Research prose

Observations now need a fetched source URL and content-word overlap with the text that run actually read. `what_they_do`, `who_they_sell_to`, and `hooks` need the same overlap or they are dropped. A matching URL alone does not keep the sentence.

Limit, stated so it is not read as a guarantee: a sentence that reuses the page's words can still be false, and a true paraphrase that shares none of those words is dropped. Signal events from providers are not passed through this check. They have their own provenance.

### Coach stream

`readCoachDeltaStream` is what Coach, Live Coaching, and Playbooks use. A test feeds the SSE body in two chunks, including a split JSON line, and reads the advice. A JSON `{ advice }` body produces an empty string, which is the contract the pages had been missing.

### Mintlify

On commit `581ece0c` the Mintlify Deployment check concluded **success**. Its log is not clean. It says `Failed to parse page content at path .lovable/north-star/north-star.md` (`Unexpected character !` from the HTML comment) and `Updated deployment with errors`. That file is Lovable's, it is on `main`, and this audit did not create it. `.mintignore` now excludes `.lovable/**` so the docs deploy does not parse it. The file itself is unchanged.
